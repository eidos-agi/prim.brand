# Delivery map

The implementation covers the requested three stages: (1) explicit versioned core, strict validation and migration; (2) asset lineage, export receipts and approval-aware releases; (3) optional richer identity capabilities and replaceable integrations.

Executable code is in `brandkit/` and `tools/`; machine-readable schemas are generated from `brandkit/schema.py`. Public minimal and comprehensive fixtures are generated by `scripts/build_examples.py`. The test suite covers negative inputs, source integrity, approval spoofing, migration, deterministic packaging, actual image export, and local MCP requests. CI runs the suite on Python 3.11 and 3.13 and verifies both real legacy packs remain unchanged.

Implemented capability contracts include visual, tokens, typography, verbal, templates, motion, sound, localization, relationships, lineage and approvals. This does not mean every consumer must declare them. Never create fake audio, translations or owner approvals just to populate fields.

The legacy house kits and validator are preserved. The existing unrelated draft brand-design PR is not merged or rewritten by this work. Private consumers and their artwork stay in private repositories; public examples use synthetic data only.

Acceptance gates not implied by implementation: independent review of the profile candidate, authenticated real-owner approval of specific reconstructed artwork or releases, legal/rights clearance, native design-tool/client certification, hosted MCP deployment and production application activation. These remain explicit rather than being hidden behind a passing format test.

Exact execution results are saved under `reports/` by GitHub CI and identify the source hashes tested. A checked-in report is evidence of its recorded run, not proof that a later revision was tested.
